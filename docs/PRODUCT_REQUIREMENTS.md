# PRODUCT_REQUIREMENTS.md

## 1. プロダクト概要

以下の構成で、ペットシッターのサービス案内と活動報告サイトを構築する。

- フロントエンド: **Astro**
- CMS: **Sanity**
- 配信: **AWS S3 + CloudFront**

本サイトは、高速・低コスト・SEO 対応・保守しやすさを重視する。

---

## 2. 目的

- ペットシッターのサービス内容と日常の活動報告を公開・閲覧できること
- 依頼を検討する人が料金、スタッフ、対応エリア、問い合わせ先を把握できること
- インフラを単純に保ち、運用コストを抑えること
- 独自バックエンド DB を持たないこと
- CMS によってコンテンツを管理できること
- コンテンツ更新後に自動リリースできること
- コンテンツ管理と公開配信を明確に分離すること

---

## 3. 利用者

### 3.1 公開閲覧者
公開済みのサービス案内と活動報告を閲覧する。

### 3.2 管理者
サイト全体設定、スキーマ管理、公開フロー管理を行う。

### 3.3 投稿者 / 編集者
Sanity 上で活動報告とサービス案内を作成・編集する。利用可能な権限は採用プランに依存する。

---

## 4. 機能要件

### 4.1 公開サイト
- ホームページ
- ご利用方法ページ
- 料金ページ
- スタッフページ
- 記事一覧ページ
- 記事詳細ページ
- カテゴリー一覧とカテゴリー別記事一覧
- アクセス・対応エリアページ
- お問い合わせページ
- 404 ページ
- RSS フィード
- Sitemap
- robots.txt

### 4.2 記事コンテンツ
各記事は最低限以下を持つこと。

- title
- slug
- excerpt
- body
- cover image
- publishedAt
- updatedAt
- categories
- seoTitle
- seoDescription
- ogImage

### 4.3 CMS
- Sanity Studio で記事を管理できる
- カテゴリーを管理できる
- スタッフを管理できる
- ご利用方法、料金、アクセス・対応エリア、お問い合わせの内容を管理できる
- サイト設定を管理できる
- draft / published を扱える

### 4.4 デプロイ
- Sanity の公開済みコンテンツからサイトをビルドできる
- 静的ファイルを S3 に配置できる
- CloudFront 経由で配信できる
- CI または Sanity webhook を契機にデプロイできる

---

## 5. 非機能要件

- 公開サイトは静的ホスティングのみ
- 公開サイトのための実行時 DB は持たない
- 低コストで運用できる
- SEO の基本を満たす
- 高速に表示される
- 運用が単純
- シークレット露出を避ける
- ローカル開発が簡単である

---

## 6. MVP では対象外

- コメント機能
- 閲覧者アカウント
- 独自バックエンド API
- 高度な検索バックエンド
- 多言語対応
- 複雑な分析基盤
- ブラウザ上でのコンテンツ編集
- ペット個体ごとのカルテ・健康記録管理
- 予約・決済システム

---

## 7. 受け入れ条件

以下をすべて満たしたら MVP 完了とする。

- 公開済みの活動報告とサービス案内が静的ページとして生成される
- 下書きが本番ビルドに含まれない
- S3 + CloudFront にデプロイできる
- SEO の基本要件が実装されている
- ドキュメントを見ればローカル起動とデプロイができる
- Sanity Studio でコンテンツ管理できる

blog-pet 向けのスキーマは #3、公開ページは #4 で実装し、AWS・Sanity への接続は #6 で確認する。
