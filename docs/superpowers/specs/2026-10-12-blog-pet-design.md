# blog-pet 移行・再構築設計

## 目的

`blog-pet` を、ペットシッターの日常の活動報告とサービス案内を両立する静的サイトへ再構築する。
将来の依頼者が、提供サービス、料金、スタッフ、対応エリア、問い合わせ先を把握し、活動報告を通じて人柄と仕事ぶりを知れることを成功条件とする。

## 採用方針

既存の `blog-tech` を基盤とし、次の固定アーキテクチャを引き継ぐ。

- フロントエンド: Astro
- コンテンツ管理: Sanity Studio
- 公開配信: AWS S3 + CloudFront
- 公開形態: ビルド時に生成する静的サイト
- 自動化: GitHub Actions

公開サイト用の独自バックエンド、RDB、閲覧者アカウント、コメント、実行時検索は導入しない。

## 公開ページとルーティング

参照サイトの情報設計を引き継ぎ、以下を公開する。

| 役割 | ルート |
| --- | --- |
| トップ | `/` |
| ご利用方法 | `/usage/` |
| 料金 | `/price/` |
| スタッフ | `/staff/` |
| ブログ一覧 | `/blog/` |
| ブログ記事 | `/blog/[slug]/` |
| カテゴリー一覧 | `/categories/` |
| カテゴリー別記事一覧 | `/categories/[slug]/` |
| アクセス・対応エリア | `/access/` |
| お問い合わせ | `/contact/` |
| 404 | `/404.html` |

トップページでは、サービス概要、主要固定ページへの導線、最新の活動報告、カテゴリーを表示する。ヘッダーとフッターには主要固定ページ、ブログ、問い合わせへの恒久的な導線を置く。

## コンテンツモデル

Sanity で以下の最小モデルを管理する。

| モデル | 用途 | 主なフィールド |
| --- | --- | --- |
| `post` | 活動報告・お知らせ・お世話のヒント | title, slug, excerpt, body, coverImage, publishedAt, updatedAt, categories, author, SEO fields |
| `category` | 記事分類 | name, slug, description |
| `staff` | スタッフ紹介 | name, slug, role, bio, avatar, social links |
| `servicePage` | 固定サービスページ | kind, title, body, heroImage, SEO fields |
| `siteSettings` | サイト全体設定 | site title, tagline, URL, 既定SEO、SNS、問い合わせ先 |

`servicePage.kind` は `usage`、`price`、`access`、`contact` を一意に管理する。スタッフ一覧は `staff` から生成する。個々のペットをカルテとして管理するモデルは MVP に含めない。

記事カテゴリーは初期値として「お仕事」「日記」「お知らせ」を用意し、Sanity で追加・変更できるようにする。

## 表示と編集の流れ

1. 管理者が Sanity Studio で記事、固定ページ、スタッフ、サイト設定を作成または更新する。
2. 公開済みコンテンツだけを GitHub Actions のビルド時に取得する。
3. Astro が全ルートを静的 HTML として生成する。
4. 生成物を S3 に同期し、CloudFront のキャッシュを無効化する。

ローカル開発では Sanity 未設定時にも画面確認ができるよう、ペットシッター向けの最小フォールバックコンテンツを提供する。本番ではフォールバックを禁止し、Sanity 接続または取得に失敗したビルドは失敗させる。下書きは公開クエリから除外する。

## 問い合わせ

問い合わせのための独自フォーム送信APIは作らない。問い合わせページは、Sanity の `siteSettings` に設定した外部リンクまたは埋め込み先を表示する。連絡手段の変更はコード編集なしで行える。

## SEO と品質

- 各ページに固有の title、description、canonical URL、OGP、Twitter Card を出力する。
- RSS、sitemap、`robots.txt` を静的生成する。
- 記事・固定ページには安定した slug ベースの URL を使う。
- 画像には代替テキストを持たせる。
- 主要画面はモバイルとデスクトップの両方を対象にする。
- CI は型・lint・ビルドを検証し、公開前チェックリストにページ、SEO、デプロイの確認を含める。

## 実装の段階

GitHub Issue で次の順に進める。

1. #2: blog-pet の基盤を整備する。
2. #3: ペット向けコンテンツモデルとサンプルコンテンツを整える。
3. #4: 公開ページとペット向けデザインを実装する。
4. #5: SEO、RSS、サイトマップを実装する。
5. #6: AWS 配信、CI/CD、運用ドキュメントを整備する。

各 Issue は前提となる Issue の完了後に短命ブランチと Pull Request で実施する。

## スコープ外

- ペット個体ごとのカルテ・健康記録管理
- 閲覧者アカウント
- コメント、いいね、独自の検索バックエンド
- 独自の問い合わせバックエンド
- 多言語対応、予約・決済システム
